description: "Maintain ScaleupMech's explicit template decisions, native checks and inert workflow candidate without changing scientific policy or runtime authority."
---

Read `AGENTS.md`, `docs/mech-template-adoption.md`, `workflow/mech-template.json`
and `INFRA_TASKS.md`. Inventory the changed canonical component and its native
prerequisites before changing an adopt/defer decision. Preserve scientific records,
history, local skills, published site policy, governed files and the governed pin.

Use the CLAW onboard-mech template lifecycle to plan and apply a reviewed source
revision. Keep domain decisions outside managed skill regions. Run `just check`,
`just check-vendored`, and `just check-template`. Compare the complete diff against
the previous adoption and prove repeat-run idempotence. Confirmed findings become
issues with fixes and independent re-review before the user decides a merge.

The workflow profile is an inert candidate. Blocked stages remain blocked until
their native adapters are implemented and reviewed. Do not install freshness,
start supervisors, activate cycles, enable auto-merge, or repin governance as a
side effect of updating template infrastructure.
